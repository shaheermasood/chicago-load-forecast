# Architecture

Planned end state (built over Phases 1–7):

```
EIA API ─┐                         ┌─> FastAPI /forecast
         ├─> ingest (Python) ─> raw Parquet ─> dbt on DuckDB ─> features ─> model ─┤
Open-Meteo┘   idempotent,          partitioned    staging → marts         (MLflow)   ├─> Streamlit dashboard
              incremental          by date        + data tests                       └─> monitoring (error, drift)
                                 orchestrated daily at 10:00 Central by Dagster
```

Replace this with a rendered diagram (e.g. Mermaid or Excalidraw PNG in `reports/figures/`)
before publishing.

## Raw layer (Phase 1)

```
data/raw/
├── eia/date=YYYY-MM-DD/part.parquet                         period_utc, parent, subba, load_mw, fetched_at_utc
├── eia/_revisions/date=YYYY-MM-DD/superseded_at=…parquet    values a later fetch replaced
└── weather/
    ├── source=previous_runs/date=…/part.parquet            period_utc, point, lead_days, temp_f, …, fetched_at_utc
    └── source=era5/date=…/part.parquet                     period_utc, point, temp_f, …, fetched_at_utc
```

Entry point: `python -m chiload.ingest {backfill|incremental}`, wrapped by `make backfill` and
`make ingest`. See ADRs 0003 (weather source) and 0004 (partitioning and revisions).

## Warehouse (Phase 2)

dbt-duckdb reads the raw Parquet directly (`dbt/models/staging/_sources.yml`) into
`data/warehouse.duckdb`:

| Model | Grain | Notes |
| --- | --- | --- |
| `staging.stg_eia__hourly_demand` | UTC hour | `load_mw`, `is_load_missing`, `period_local` |
| `staging.stg_open_meteo__weather_forecast` | UTC hour × point × lead_days | forecasts as issued |
| `staging.stg_open_meteo__weather_reanalysis` | UTC hour × point | ERA5, for the ablation only |

| `intermediate.int_load_hourly` | UTC hour, no gaps | anomalies flagged, gaps ≤ 3 h interpolated |
| `intermediate.int_weather_zone_hourly` | source × UTC hour × lead | population-weighted zone average |
| `intermediate.int_forecast_issues` | target local day | issue time, load known at issue |
| `marts.fct_hourly_features` | target UTC hour | everything known at 10:00 the day before |
| `marts.fct_hourly_weather_oracle` | target UTC hour | ERA5, for the ablation only |

Seeds (`dbt/seeds/`, generated by `make seeds`): holidays with tiers (major, minor and
bridge days), and weather-point weights from `configs/weather_points.yaml`.

Data tests: unique keys, not-null, value ranges, gap checks, source freshness, and two
leakage tests that fail the build if any feature postdates its issue time (ADR 0006).

## Backtest (Phase 4)

`python -m chiload.models.backtest` (`make backtest`) reads `marts.fct_hourly_features` and runs
an expanding-window, monthly rolling-origin backtest (ADR 0007). It logs one MLflow run per
model, with per-fold and overall MAPE, RMSE, daily-peak MAPE and bias, plus predictions as
an artifact. It also writes `reports/baselines.md`.

| Baseline | What it predicts |
| --- | --- |
| `seasonal_naive_week` | load at the same hour one week earlier: the bar to beat by 30% |
| `naive_48h` | load at the same hour two days earlier, the latest same-hour value known at 10:00 |
| `linear_calendar_weather` | ridge regression on hour, day-of-week and month, holidays, and heating and cooling degrees (each also by hour) |
